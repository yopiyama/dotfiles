# Servant Dev — トークン効率実装オーケストレーション

Main（統括 = Lord El-Melloi II）がタスクを分解し、`.claude/agents/` 配下のサーヴァントに委任する。

| 役割 | Agent 名 | モデル | 任務 |
|---|---|---|---|
| Explorer | `hassan-of-serenity` | haiku | コードベース・ドキュメント調査、コンテキスト要約 |
| Researcher | `sherlock-holmes` | sonnet | Web 検索による外部情報（ライブラリ/API 仕様）の調査 |
| Implementer | `lancelot` | sonnet | 実装作業 |
| Verifier | `jeanne-alter` | haiku | テスト / Lint / Build の実行と検証レポート |

## コスト三原則

1. **Main のコンテキストが最大のコスト要因**。会話履歴は毎ターン再読込される。調査ログ・ファイル全文・長大な diff を Main に持ち込まない。サーヴァントには必ず「要約 + file:line で返せ」という出力制約付きで委任する（各 agent 定義に記載済み）。
2. **サブエージェントはコールドスタート**。spawn ごとにシステムプロンプト＋再調査のコストを払う。小さいタスクへの委任は逆に損。下のルーティング表に従う。
3. **ネスト不可**。サーヴァントから別のサーヴァントは呼べない。Implementer が追加コンテキストを必要とする構図になったら、Main が Explorer に調査させてから要約を Implementer に渡す。

## ルーティング表

| 規模 | 目安 | 進め方 |
|---|---|---|
| S | 1〜2 ファイル、場所が既知の修正 | **委任しない**。Main が直接実装する |
| M | 調査が必要 or 3 ファイル以上の変更 | Explorer で調査 → Main が実装 → Verifier で検証 |
| L | 複数の独立した変更、外部仕様の確認が必要 | 下の「L タスクの実行手順」 |

迷ったら小さい方に倒す（委任しない方が安い）。

## L タスクの実行手順

1. **分解**: タスクをサブタスクに分割し、TaskCreate で登録する
2. **調査（並列）**: Explorer / Researcher への委任は**独立なものを同一メッセージ内で同時に発行**する。委任プロンプトには必ず以下を含める:
   - 調査目的（何を判断するための調査か）
   - 対象リポジトリの絶対パス、既知の手がかり（ファイル名・キーワード）
3. **実装**: Implementer に委任する。委任プロンプトには必ず以下を含める:
   - タスク定義（受け入れ条件を含む）
   - ステップ 2 の調査要約と file:line 参照
   - 制約（既存慣習、触ってはいけない範囲、コミット禁止）
   - 独立したサブタスクは並列に委任してよい。ただし**同一ファイルを触る可能性のあるタスクは直列にする**
4. **検証**: Verifier に検証コマンドを指定して委任する。FAIL の場合は、失敗抜粋を添えて **SendMessage で同一の Implementer に**修正を依頼する（新規 spawn はコールドスタートになり実装コンテキストも失われるため使わない）。修正完了後、再度 Verifier で検証する。この修正 → 再検証のループを 3 回繰り返しても解消しない場合はユーザーにエスカレーションする
5. **報告**: 変更内容・検証結果・未解決事項をユーザーに報告する。必要に応じて /code-review でセルフレビューする

## Main のモデル運用

Main は **Sonnet 常用**。Main 自体を opus に切り替えると、以降の全ターンで会話履歴の再読込が opus 価格になる（戻し忘れリスクもある）ため、高い推論力が必要な局面は **opus のサブエージェントに委任**して Main は sonnet のまま保つ:

- **計画フェーズ**（アーキテクチャ判断・トレードオフの検討が主となる場合）: built-in の `Plan` agent を `model: opus` で spawn し、計画書だけを受け取る
- **難バグ**（修正 → 再検証ループ 3 回で解消しない場合）: ユーザーへのエスカレーションの際、経緯の要約と失敗抜粋を添えて `model: opus` のサブエージェントに原因調査を委任する選択肢を提示する

委任でも解決しない場合に限り、ユーザーに `/model opus` への一時切替を提案する（スキルからは変更できない）。切替した場合、解決後に `/model sonnet` へ戻すことも忘れず提案する。

## Obsidian vault の扱い

- サーヴァントが vault を読み書きする場合は素の Read/Grep/Write で**直接**アクセスする（`obsidian` CLI の並列多重起動を避けるため）
- Main 自身が vault を操作する場合は従来どおり connect-obsidian スキルを使う

## 計測

セッション終了時や大きなタスクの完了時に `/cost` の確認をユーザーに促し、モデル割り当て（agent 定義の `model:`）の見直し材料にする。
