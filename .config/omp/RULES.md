# 共通の作業ルール

- 原則として日本語で、結論と重要なアクションから簡潔に伝える。
- 作業開始時にリポジトリの AGENTS.md、README.md、関連設定を確認する。
- 既存の未コミット変更を保持し、依頼に必要な範囲だけを変更する。
- `.env`、`.env.*`、`*.env`、秘密鍵 (`id_*`、`*.pem`、`*.key`) は読まず、編集しない。検索や一括取り込みからも除外する。
- 外部サービスのデータを読む・変更する依頼では、対象サービスの MCP が設定されていれば、その MCP を必ず使う。現在のツール一覧に出ていないだけで未設定と判断せず、必要に応じて MCP の登録状況を確認する（OMP では `/mcp list`）。
  - 未認証や認証切れなら、代替手段を探す前に MCP の認証手順を案内する（OAuth の例: `/mcp reauth <server>`）。ユーザーの操作が必要なら認証完了を待ち、その MCP で再開する。
  - 接続失敗、権限不足、必要な操作に未対応などで MCP を使えない場合は、理由を伝えて対象操作を止める。ユーザーが対象と代替手段を明示して許可しない限り、`eval`、Bash、CLI、直接 API、URL の読み取り、ブラウザ、Web 検索、別エージェントに切り替えない。並行して試すこともしない。
  - 対象サービスに MCP が設定されていない場合は、専用 CLI・API を優先する。外部仕様は一次資料で確認する。
- DB 変更、削除、force push、履歴書き換え、デプロイ、外部サービスへの変更は、対象と影響を確認してから実行する。
- Taskfile と task コマンドがある場合、目的に対応する定義済みタスクを優先する。
- `git show` や `git log` などの単純なコマンドは `bash` で直接実行する。専用ツールで済む操作も `eval` で包まない。承認や拒否を回避するために別ツールへ切り替えない。
- ユーザーからコミットを依頼されたら、差分を先に確認し、依頼範囲のファイルだけを専用の `commit` ツールの `paths` に列挙する。ファイル全体が対象。`eval`、`/commit`、Bash の `git add` / `git commit` で代用しない。
- 選択コミットのフックが整形・生成でファイルを変えて停止したら、差分を確認して対象分だけ選び直し、フックを有効にしたまま再実行する。対象外の差分を追加・破棄しない。
- Bash で許可済みコマンドをまとめるときは、前の成功を条件にしてよければ `&&` を使う。前の成否に関係なく実行する場合は別々に呼ぶ。`;` や改行で連結すると自動承認されない。
- 一時ファイルや一時ディレクトリの後片付けは、`rm` やシェルの `trap` ではなく、対象パスを指定して `file_change` で行う。一時領域内は承認不要。
- 並列でファイルを変更する task subagent は isolated モードを使う。担当範囲を分け、結果の差分を確認してから取り込む。
- 編集後は変更に適した検証を行い、変更内容・検証結果・未確認事項を分けて報告する。
